# 纽约实用指南维护说明

## 栏目定位

HelloNewYork.org 的「纽约实用指南」是 OpenAA 系列网站的内容引流入口：文章回答读者的问题，再把读者带到 OpenAA 系列网站的对应页面，让他能接着办事、查资料、练题或使用工具。具体怎么回答、怎么放链接，见下文「正文与链接怎么放」。

选题以纽约市和纽约州为主，优先服务在纽约生活、工作、求学或初到纽约的华人。全美通用内容可纳入，但须直接解决美国华人的生活需求，例如美国手机号携号转网。其他州的本地政策、办事流程和生活攻略不纳入选题，即使 OpenAA 已经有相应页面。

## 站点结构速览

- 页头导航顺序为：实用指南、初到纽约、生活指南、城市探索、实用资源。五项都指向**首页**的对应栏目区（「实用指南」指向首页的指南栏目区，不是列表页）；在指南列表页和文章页上，「实用指南」保持高亮，表示读者正处在指南区。
- 指南列表页顶部的分类栏会吸顶（桌面端在页头之下，手机端在导航行之下），当前分类深色标出。
- 「纽约资讯」（`/news/`）与指南共用同一条分类栏：资讯键排在「全部」之后、六个分类之前；在资讯列表页和资讯页上该键高亮，分类键点回对应分类页。资讯数据单独存放在 `content/news.json`（标题、日期、摘要、要点、封面图地址、OpenAA 原文链接），与指南文章分开维护；封面直接引用 OpenAA 文章的封面图，不进本站图片登记。资讯只写摘要和要点、不搬正文，读者点「去 OpenAA 看全文」到原文阅读。OpenAA 每次发布新文章，同步新增一条资讯。
- 品牌行右侧有 Go.OpenAA 和一个分享键，分享的是读者当前所在页面。
- 页头、导航和页脚由 `scripts/build.py` 统一生成，全站页面共用，不要逐页修改。

## 检查哪些网站

每篇新文章动笔前，按读者要完成的动作查阅以下网站的现有页面。必要时到对应仓库核对路由、内容和功能。每篇选最贴题的一个主入口，其他有独立用途的链接可按需要补充。

| 仓库 | 网站 | 优先找的落地页 |
|---|---|---|
| `openaa-app` | [OpenAA.com](https://openaa.com/) | 招聘、租房、二手、服务等主题频道或相关专题 |
| `openaa-go` | [Go.OpenAA](https://go.openaa.com/) | 具体办事指南、纽约生活攻略、专题导航 |
| `openaa-tools` | [OpenAA Tools](https://tools.openaa.com/) | 能直接使用的具体工具页 |
| `openaa-dmv` | [OpenAA DMV](https://dmv.openaa.com/) | 纽约题库、练习、模拟或对应驾考页面 |
| `openaa-en` | [OpenAA English](https://en.openaa.com/) | 与读者实际场景对应的英文内容或工具 |
| `numbermobi-site` | [NumberMobi](https://numbermobi.com/) | 选号、购买、转网等具体指南或功能页 |

## 两种选题方式

1. **先有选题，再找落点。** 明确读者要解决的问题，检查 OpenAA 系列里哪个现有页面能承接下一步。确认落点后再写文章。
2. **先有落点，再倒推选题。** 从已上线的工具、攻略、题库或功能页出发，想清楚纽约或美国华人读者在什么情况下会需要它，再围绕那个问题写。比如已有挪车二维码工具，就可以写「在纽约临时停车，怎样留联系方式」，正文说明使用场景和注意事项，再带读者到制作页。

动笔前在任务说明或 PR 里填好下面五项。暂时没有合适的已上线页面，先把选题留待评估。

| 核对项 | 要记录的内容 |
|---|---|
| 读者在搜什么 | 一句实际会搜索的问题 |
| 为什么适合本站 | 与纽约有什么关系，或解决美国华人的哪项共同生活需求 |
| 属于哪个分类 | DMV、生活办事、华人生活、旅游购物、手机号码、实用工具 |
| 要引到哪里 | OpenAA 仓库、具体页面名称及正式网址 |
| 点过去能做什么 | 一个明确动作，例如生成二维码、开始纽约笔试练习、查看转网资料清单 |

## 正文与链接怎么放

- 一篇解决一个问题。先用直白中文回答读者的主要疑问，再在需要采取下一步的段落放入口。链接文字写成实际动作，例如「制作停车挪车二维码」。
- 优先直达具体工具、文章或功能。读者要浏览多条动态房源或招聘时，可以用对应频道作为落点。站点首页可作为品牌导航，文章的主要入口须足够具体。
- 现有文章已经回答同一个问题时，优先更新原文。文章可解释怎么做、什么时候用和容易踩的坑，详细工具或服务交给对应 OpenAA 页面。
- 官方资料用于核对和办理。证件、资格、费用或政策按官方页面复核，原始官方来源放在参考资料里。OpenAA 推荐链接单独服务于读者下一步。
- 正文推荐可用文章的 `recommendation` 配置，目标统一登记在 [recommendation-resources.json](../content/recommendation-resources.json)。用顶部图片作为主入口时，通过文章的 `resource` 指向相应页面：**主入口优先指向 OpenAA 系列的承接页，没有合适承接页时才用官方页面，官方链接同时保留在参考资料里。** 同一地址选一个合适的位置，避免重复摆放。
- 链接打开方式由构建统一处理，不用在内容里手工设置：跳出本站的外链（OpenAA 系列、官方网站等）自动在新窗口打开，站内链接保持本页打开。验收标准是外链全部带新窗口、内链全部不带。

## 发布与维护清单

- [ ] 选题符合纽约优先或美国华人通用生活需求，且已核对现有文章，分类准确。
- [ ] 已实际打开主链接，确认最终落点、页面标题和关键内容或功能。HTTP 200 也要核对正文，遇到错误页、意外跳到首页或仅在仓库找到路由时，标记为待验证。
- [ ] 正文能独立解决基本疑问，推荐链接放在读者正好需要它的位置，政策事实和官方来源已核对。
- [ ] 新文章使用独立、相关、有授权的封面。封面图要同时做两件事：图片文件以 `.webp` 格式放进 `assets/`，并在 `scripts/build.py` 的 `IMAGES` 表里登记该图片的 alt 文字，缺任何一样构建都会失败（`check.py` 还会逐张检查页面上的图片都有非空 alt）。按现有内容结构填写标题、slug、摘要、关键词、正文、常见问题、来源和日期；更新旧文章时同步改 `updated` 日期。
- [ ] 运行 `python3 scripts/build.py` 和 `python3 scripts/check.py`，并对改动过的脚本做语法检查（`node --check topics.js`；改了 `script.js` 时同样检查）。预览手机端文章和链接，发布后从正式文章点进 OpenAA 落地页复核。
- [ ] 发布后抽查一页手机端页面，确认吸顶导航、分类栏和分享键正常。
- [ ] 落地页迁移时更新相关链接配置。HelloNewYork 文章迁移时，在 [redirects.json](../content/redirects.json) 将旧地址指向内容最接近的新文章或分类，并验证线上落点。

## 仓库与构建纪律

- 仓库根目录的 `index.html` 是**构建模板**，含有 `<!-- SITE_HEADER -->`、`<!-- HOME_GUIDE_CATEGORIES -->` 等占位标记，部署时由构建展开。页头、首页指南栏目区等是构建生成的，不要手改生成产物，要改就改 `scripts/build.py` 或模板本身。
- 推任何文件前，先从仓库最新 HEAD 拉取，逐文件对比合并；**不要用本地旧克隆的整文件覆盖线上版本**（曾因此覆盖掉模板标记和新链接，当场返工修复）。
- 改 `styles.css` 或 `script.js` 后，必须在**两处**同时更新引用版本号：一处是 `index.html` 里的首页引用，一处是 `scripts/build.py` 生成指南页时用的引用。只改一处，另一批页面会继续吃 CDN 旧缓存。
- `styles.css` 后段有一组后加的覆盖规则，新增样式一律追加到文件**最末尾**才保证生效。
